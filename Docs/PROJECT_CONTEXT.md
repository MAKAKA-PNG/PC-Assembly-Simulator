
# Контекст PC Assembly Simulator

## 1. История проекта

Первоначально разрабатывалась другая игра —
«Лабиринт Бездны».

Затем концепция была изменена на образовательную
3D-игру по сборке персонального компьютера.

Проект создаётся для курсовой работы студента
4-го курса колледжа.

Тема курсовой:
«Разработка компьютерной игры на движке Unity».

Важно: это именно компьютерная игра с обучающими
механиками, а не просто просмотрщик 3D-моделей.

## 2. Цель

Игрок изучает компьютерные комплектующие,
устанавливает их в корпус, подключает необходимые
разъёмы и проверяет правильность сборки.

Планируются два режима:

Обучение:
- Пошаговая установка компонентов.
- Подсказки.
- Объяснение ошибок.

Практика:
- Самостоятельная сборка.
- Итоговая диагностика.
- Оценивание результата.

## 3. Технологии

Unity 6, URP, C#, Visual Studio 2022.

Целевая платформа: Windows.

Приложение должно работать локально.

Планируются готовые реалистичные 3D-модели.
На этапе разработки используются простые
временные объекты.

## 4. Основные комплектующие

- Корпус
- Материнская плата
- Процессор
- Кулер процессора
- Два модуля оперативной памяти
- Видеокарта
- Блок питания
- SATA SSD

## 5. Используемые скрипты

OrbitCameraController:
Управление орбитальной камерой.

HardwareComponentData:
Данные комплектующих через ScriptableObject.

HardwareComponentView:
Связь модели с данными компонента.

ComponentSelectionController:
Выбор объектов на сцене.

PlacementController:
Установка компонентов.

ComponentSlot:
Посадочное место и SnapPoint.

AssemblyValidator:
Проверка полноты сборки.

CompatibilityChecker:
Проверка совместимости комплектующих.

ConnectorPort:
Описание разъёма.

ConnectionManager:
Выбор и регистрация соединений.

ComponentInfoPanel:
Показ сведений о компоненте.

## 6. Подтверждённый прогресс

Пользователь подтвердил работу:
- Орбитальной камеры.
- Выбора комплектующих.
- Информационных карточек.
- Первого подключения ATX 24-pin.

Установка процессора ранее проверялась
визуально, но полная работа всех слотов
ещё не подтверждена.

AssemblyValidator и CompatibilityChecker
добавлены в сцену, однако их полная
работоспособность требует проверки.

Не следует считать все подготовленные
скрипты полностью протестированными.

### Установка комплектующих

В Workshop у всех восьми подвижных деталей есть посадочные места. Добавлены MB_TRAY,
CPU_COOLER_MOUNT и SSD_BAY. Монтажная зона Assembly остаётся неподвижной.
CPU, оба модуля RAM и GPU требуют установленной платы; кулер требует установленного CPU.
Блок питания и SSD можно установить независимо. Для перекрывающихся коллайдеров
луч выбирает ближайший слот нужного типа. При отсутствии такого слота сохраняется
сообщение о неверном типе. Панель проверки установки закрывается клавишей Esc.

Автопроверка в Play Mode прошла через обработчики выбора и установки с виртуальной
мышью: предпросмотр и отмена платы, отказ при попытке поставить CPU до платы и в
неверный слот, установка всех восьми деталей и сверка их слотов и родителей.
Валидатор отклонил пустую сборку и принял 8 из 8. После установки все шесть пар
зарегистрировались через TryConnect. Из стартового ракурса центры всех 12 портов
доступны лучу выбора разъёмов. Ручная оценка удобства и проверка совместимости впереди.

## 10. Принцип работы

Пользователь хочет двигаться достаточно быстро:
желательно выполнять связанные задачи крупными
этапами, а не требовать множество скриншотов.

Работающие системы не следует переделывать
без явной технической причины.

Непроверенные функции необходимо отделять
от подтверждённых.

Перед значительными изменениями требуется
резервная копия или Git-коммит.

После каждого этапа желательно фиксировать
изменения и оставшиеся задачи.
